# FILES CHANGED

Modified tracked source files:

1. src/main/ipc/systemIpc.ts
   - What changed: Full rewrite. Kept pick-exe / pick-image / pick-log (each now
     rejects untrusted senders). Replaced the raw `shell.openPath(exePath)` call
     in launch-game with a library-allowlist check (`isRegisteredExePath`).
     Added new channels: open-external (https-only), open-folder (folder
     allowlist), power-save-start / power-save-stop, overlay-send,
     app-get-path (name allowlist), system-get-stats. scan-games now returns []
     instead of an unimplemented stub body.
   - Why it changed: The previous launch-game let the renderer open ANY path on
     disk, which is a local arbitrary-exec vulnerability. Phase 2 also required
     the new system/overlay/power channels.

2. src/main/ipc/gameIpc.ts
   - What changed: Added the `db-add-session` handler (gameId, minutes, stats ->
     SqliteSessionRepository.add). Existing zaiken:games:get-all/save/update/
     delete handlers were left as-is.
   - Why it changed: The renderer needs a manual way to log playtime/stats for a
     game outside the live session flow.

3. src/main/ipc/profileIpc.ts
   - What changed: Added the `db-record-match` handler (validates via
     recordMatchSchema, calls SqliteProfileRepository.recordMatch, then
     re-evaluates achievements). zaiken:profile:get and zaiken:profile:save now
     check isTrustedSender.
   - Why it changed: Match recording was required for the profile/rank UI; the
     existing profile handlers had no sender validation.

4. src/infrastructure/database/repositories/SqliteProfileRepository.ts
   - What changed: Added `recordMatch()` (accumulates totalWins/totalLosses/
     totalKills/totalDeaths/totalMatches, updates winStreak and bestWinStreak,
     recomputes rank via computeRank). Added import of computeRank.
   - Why it changed: The profile screen needed a persistence method for match
     results that also maintains streak + rank invariants.

5. src/main/bootstrap.ts
   - What changed: Imports and calls for registerWindowIpcHandlers,
     registerSessionIpcHandlers, registerStatsIpcHandlers,
     registerLogsIpcHandlers, registerAiIpcHandlers.
   - Why it changed: New IPC handler groups must be registered after the
     database is initialized.

6. src/main/ipc/validationSchemas.ts  (added during Phase 2, then fixed)
   - What changed: Fixed `z.record(z.unknown())` -> `z.record(z.string(),
     z.unknown())` for zod v4 (the v3 one-argument form is not valid in zod 4).
   - Why it changed: `npx tsc --noEmit` reported TS2554; this was the only way to
     typecheck cleanly against the installed zod ^4.4.3.

# SECURITY FIXES

1. Severity: HIGH
   - File: src/main/ipc/systemIpc.ts (launch-game)
   - Vulnerability: Renderer could launch any executable path on disk via
     shell.openPath (arbitrary program execution).
   - Fix: launch-game now requires the exePath to exactly match a game's
     registered exePath in the library (case-normalized). Existence on disk is
     not the security boundary; allowlist membership is.
   - Verification status: Verified by code inspection; tsc / lint / npm test pass.

2. Severity: HIGH
   - File: src/main/ipc/logsIpc.ts
   - Vulnerability: Renderer could read/hash/watch arbitrary files by passing any
     path to the log channels.
   - Fix: Every log channel resolves the path through isRegisteredLogPath(games);
     non-registered paths are refused ("Refused: path is not a registered game
     log") before any fs call.
   - Verification status: Verified by code inspection; build/test pass.

3. Severity: MEDIUM
   - File: src/main/ipc/systemIpc.ts (open-external)
   - Vulnerability: Arbitrary protocol navigation from the renderer
     (e.g. file://, custom protocols) via shell.openExternal.
   - Fix: Only https:// URLs are accepted (isSafeHttpUrl).
   - Verification status: Verified by code inspection.

4. Severity: MEDIUM
   - File: src/main/ipc/systemIpc.ts (open-folder)
   - Vulnerability: Renderer could ask the OS to open any folder.
   - Fix: Folder must be the parent of a registered game's exePath or logPath
     (isRegisteredFolder); otherwise ignored.
   - Verification status: Verified by code inspection.

5. Severity: MEDIUM
   - File: src/main/ipc/systemIpc.ts (app-get-path)
   - Vulnerability: Renderer could call app.getPath with arbitrary path names.
   - Fix: Whitelist of allowed names (userData, appData, home, temp, cache, logs,
     documents, downloads, music, pictures, videos, desktop); anything else
     returns null.
   - Verification status: Verified by code inspection.

6. Severity: MEDIUM
   - File: all new/rewritten handlers (windowRegistry.ts isTrustedSender)
   - Vulnerability: Untrusted webContents could invoke IPC channels.
   - Fix: isTrustedSender checks the sender webContents id against the set of
     windows this app created (plus a file://.../renderer/ URL fallback); all
     Phase 2 handlers reject unauthorized senders.
   - Verification status: Verified by code inspection. (Note: pre-existing
     handlers in auth/settings/supabase/achievements and zaiken:games:* do NOT
     yet use it — listed under REMAINING ISSUES.)

7. Severity: LOW
   - File: src/main/ipc/aiIpc.ts
   - Vulnerability: Renderer UI would hang indefinitely if the AI server is not
     running or has no API key.
   - Fix: ai-ask / ai-daily-report / ai-daily-reports-batch probe /health with a
     1.5s timeout and return { ok:false, needsSetup:true } with an explicit
     message instead of waiting forever; fabricated coach answers are never
     returned.
   - Verification status: Verified by code inspection.

8. Severity: LOW
   - File: src/main/ipc/logsIpc.ts (read-log-tail)
   - Vulnerability: Renderer could request unbounded log line counts.
   - Fix: clampLogLines caps requested lines to 1..2000.
   - Verification status: Verified by code inspection.
